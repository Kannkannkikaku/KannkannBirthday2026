# 本番切り替え手順（11/16 12:00）

> このファイルは GitHub にも公開されます。駅名・掲出場所の詳細は**書かないでください**（11/16 12:00 まで公開禁止のため）。

駅広告の規約で、**掲出当日 2026/11/16 12:00（日本時間）より前**に、駅名などの詳しい場所を公開してはいけません。
そのため、今公開しているサイト（main ブランチ）は「〇〇県某所」表記の**審査用**になっています。
本番の表記と本物のマップは、このPCだけにある **`release-1116` ブランチ**に入っています。

---

## しくみ

```
main（GitHub に push してよい・審査用）
 ├─ 2308de3 ハッシュタグ案内の文言変更・駅広告イラストのファイル名を整理   ← 本番でもそのまま
 └─ 183b19e 駅広告の審査用表記に変更                                         ← 審査用
      └─ release-1116（このPCだけ・push 禁止）
           └─ [本番用] 掲出場所の表記と掲出場所マップを本番の内容に戻す     ← これを 11/16 12:00 に main へ取り込む
```

- `release-1116` の一番上の **`[本番用]` コミット1つ**に、本番に戻すための変更がすべて入っています。
  - お知らせの11/16の文の掲出場所（「〇〇県某所」→ 本番の駅名）
  - イラストページの駅名（掲出場所・画像の説明・meta）
  - トップのスライドショーの画像の説明
  - インフォメーションページの中身（駅名・場所・行き方・注意書き）
  - 本物のマップ画像 `images/stations/map-kanagawa.png`・`map-tokyo.png`・`map-aichi.png`
- 11/16 12:00 には、この1コミットを main に取り込んで push するだけです。
  それまでに main で行った変更（イラストの差し替え、お知らせの追加など）は消えません。

### うっかり公開を防ぐしくみ（pre-push フック）

`.git/hooks/pre-push` に、次の2つを止める設定を入れてあります（このPCだけ）。

1. `release-1116` ブランチの push（いつでも）
2. 11/16 12:00 より前の、`[本番用]` コミットを含む push

VS Code の「変更の同期」「ブランチの発行」などで誤って押してもエラーになり、push されません。

## 全体の流れ

| 時期 | やること | 公開サイトの中身 |
|---|---|---|
| 〜審査OK | 審査用のまま公開しておく | 審査用 |
| 〜11/15 | 本番の素材（マップなど）がそろったら `release-1116` 側に入れておく（下の「11/16 までに本番の内容を直したいとき」） | 審査用 |
| **11/15 深夜** | **PCの中だけで**完成版に切り替え、Live Server で全ページを確認する。**push はしない** | 審査用 |
| **11/16 12:00** | push する（「変更の同期」ボタン1回） | 12:01〜12:02 ごろ完成版に |

- リポジトリを非公開にする必要はありません（非公開にすると無料プランでは GitHub Pages が止まり、公開に戻すときに再設定が必要になることがあるため）。
- 11/15 深夜〜11/16 朝にうっかり「同期」を押しても、12:00 より前はフックが止めてくれます。
- 12:00 に push しても反映は 1〜2 分後なので、「12:00 より前に公開」にはなりません。

## 11/15 深夜：PCの中で完成版に切り替えて確認する

VS Code のターミナル（メニューの「ターミナル → 新しいターミナル」）で、上から順に実行します。

### 1. main にいることを確認し、最新にする

```bash
git checkout main
git pull
```

### 2. 本番用のコミットを main に取り込む（まだ push しない）

```bash
git cherry-pick release-1116
```

- 「conflict（競合）」と出たら、11/16 までに main 側で同じ行（お知らせの11/16の文やインフォメーションページなど）を変えていたということです。
  VS Code のソース管理に競合したファイルが表示されるので、本番の表記（駅名が入っている方）を選んで保存し、次を実行します。

  ```bash
  git add -A
  git cherry-pick --continue
  ```

- 取り込めたかの確認：

  ```bash
  git log --oneline -3
  ```

  一番上が `[本番用] 掲出場所の表記と掲出場所マップを本番の内容に戻す` になっていれば OK です。

### 3. Live Server で確認する

1. VS Code の右下の「Go Live」を押す（または `index.html` を右クリック →「Open with Live Server」）
2. ブラウザで `http://127.0.0.1:5500/index.html` が開く（自分のPCの中だけ。ほかの人には見えません）
3. 下のチェックリストを確認する
4. 終わったら右下の「Port : 5500」を押して止める

**チェックリスト**（日付による表示は、URL の末尾に `?preview-date=2026-11-16T12:00` などを付けると確認できます）

- [ ] トップ：オープニング演出が流れる／スキップできる／「オープニングをもう一度見る」で再生できる
- [ ] トップ：駅広告のスライドショーが切り替わる（左右タップ・スワイプ・ドット）
- [ ] トップ：お知らせの掲出場所が「〇〇県某所」ではなく本番の駅名になっている
- [ ] トップ：「ハッシュタグをコピー」で文字がコピーできる
- [ ] トップ：カウントダウン（`?preview-date=2026-11-19`・`2026-11-21`・`2026-11-23` でも確認）
- [ ] メッセージ：カードが流れる／タップで拡大／指でスライド／「一覧で読む」
- [ ] イラスト：掲出場所が「〇〇県某所」ではなく本番の駅名になっている／絵師さんのリンクが開く
- [ ] インフォメーション：場所の詳細・注意書き・本物のマップが表示される／マップをタップで拡大できる
- [ ] スマホ幅でも崩れていない（ブラウザの開発者ツールで幅 375px にして確認）

> 確認したまま、**push はしないで**そのまま 11/16 12:00 を待ちます。
> 直したいところが見つかったら、main で直してコミットして大丈夫です（push しなければ公開されません）。

## 11/16 12:00：公開する

### 4. push する（12:00 を過ぎてから）

```bash
git push origin main
```

または VS Code のソース管理の「変更の同期」でも OK です。
12:00 より前に実行すると、フックが止めてくれます（エラーになっても壊れてはいません。時間を待ってもう一度実行してください）。
判定はこのPCの時計で行うので、PCの時刻がずれていないか事前に確認しておくと安心です。

### 5. サイトで確認する

1〜2分後に次のページを開き、駅名・場所・マップが表示されているか確認します。
ブラウザに古いファイルが最大10分残るので、PCは `Ctrl + Shift + R`、スマホはタブを閉じて開き直してください。

- トップ：お知らせの掲出場所が「〇〇県某所」ではなく本番の駅名になっている
- イラスト：掲出場所が「〇〇県某所」ではなく本番の駅名になっている
- インフォメーション：場所の詳細・注意書き・本物のマップが表示される

## 11/16 までに本番の内容を直したいとき

本物のマップを差し替えたい、本番の場所の説明を直したい、などのときは `release-1116` 側で直します。
**main では直さないでください**（main は公開されるため）。

```bash
git checkout release-1116
# ファイルを編集・画像を上書き（images/stations/map-*.png）
git add -A
git commit --amend --no-edit     # [本番用] コミット1つにまとめたままにする
git checkout main                # 作業が終わったら必ず main に戻る
```

- `--amend` を使うのは、本番用の変更を **1つのコミット**にまとめておくためです（手順2の cherry-pick が1回で済みます）。
- `release-1116` にいる間は、VS Code の画面に本物の駅名・マップが表示されます。作業が終わったら必ず `git checkout main` で戻ってください。

## 間違えて main に取り込んでしまったとき（11/16 より前）

push する前なら、次で取り消せます（push はフックが止めてくれます）。

```bash
git reset --hard origin/main
```

> ⚠ `reset --hard` は、まだコミットしていない変更も消します。心配なときは相談してください。

## 切り替えた後に元（審査用）に戻したいとき

```bash
git revert HEAD
git push origin main
```
